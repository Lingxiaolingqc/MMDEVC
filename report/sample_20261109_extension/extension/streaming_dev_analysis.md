# dev_tokyo_100：VDA offline / streaming 独立分析

日期：2026-11-09。相同 Small 相对权重、FP16、input_size=364、8 CPU threads、相同 RGB/PTS，RTX 4060 Laptop GPU。没有训练、GT 对齐或 metric-video。

## 控制与核验

两模式分别在单独进程内预热，随后同一模型运行三次；每次 streaming 完全清空时间缓存。重放前三帧与完整序列前三帧最大绝对差为 0；三次输出相同。新 offline 与旧保存 offline 最大差为 0.0。原结果不覆盖。

计时从内存 RGB 开始，到返回 CPU float32 深度结束；CUDA 同步，排除模型加载、视频解码、写盘和渲染。表中的首次返回：offline 官方接口一次返回整段，streaming 返回第一帧。输入已在内存，不含等待真实视频帧的时间；该列不是模型固有首帧延迟。

| 模式 | 总时长中位数 s（范围） | FPS 中位数 | 首次 API 返回 ms | 后续单帧 median/P95 ms | 峰值 allocated/reserved MiB | T |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| offline | 9.585 (7.687–9.810) | 10.433 | 9584.66 | — | 2386.4/3178.0 | 0.002941 |
| streaming | 5.734 (5.694–5.773) | 17.441 | 69.10 | 56.47/60.21 | 685.3/806.0 | 0.003580 |

Streaming 的 T 比 offline 高 21.71%。二者在同一 RGB/flow 参考区域计算，coverage 都为 1，但各用自己的整段跨度，且无视频深度 GT，因此不是准确率下降百分比。原始相对 L1 和显示范围见 [comparison.csv](comparison.csv)。首个帧对在 streaming 曲线中有较大尖峰，后续也有差距；不能将全部差距归于首帧。

## 独立视觉复核

实际查看了均匀全景、四组连续 ROI 和诊断图；不是完整实时播放。帧号与 ROI 保存在 review.json。

0–5 帧：streaming 首帧上身/肩部有较暗的不均匀色块，下一帧起明显减弱；offline 上身较均匀。两者都保留主要行走轮廓，鞋与地面仍合并。

28–33 帧：头、外套、摆动的手和包的轮廓非常接近；存在细微颜色和局部边界差异，没有建立整体形状优劣。

60–65 帧：两者均保留宽轮廓，衣摆、包与腿部仍简化。未见 streaming 新增明显宽拖影。

94–99 帧：主体轮廓接近，两者腿部都逐渐融入地面；所看末段未出现明显持续恶化，但这不是长视频结论。

## 结论与限制

本机短片实验显示 streaming 使用更少显存、整体返回更快，代价是更高的时序变化诊断和可见初始化差异；大部分被检查的轮廓仍接近。只报告这种取舍，不声称深度精度或长时间稳定性。

三次重复来自同一片段，模式按块顺序运行，没有随机交替或严格控制热状态/其他系统负载。计时范围已给出，不能与旧单次结果直接混用。过山车 24 fps 要求每帧约 41.67 ms；当前 streaming 中位数超过此值，不能称原帧率实时。全段固定色标用于离线审阅，不冒充在线色标算法。

源码 scripts/part2_models/run_vda_mode.py 对原始数组和计时负责，最终结论以本文件与 review.json 为准。全部视频时间戳通过解码核验。旧用户观察未作为结论依据。
