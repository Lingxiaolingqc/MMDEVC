# 评测协议草案 v0.1

主维护：A / Qinchuan XIAO；复核：B / Jun Yu Eugene YIP。

课程版本已确认 Spring 2027。本文中的原则已约定；具体 crop、范围、数据划分文件与边界/时序公式须结合数据和参考实现核对，填写后才可冻结正式评测。

## 已约定原则

1. 区分直接 metric 与 relative/aligned 两套结果。直接 metric 评测不利用测试 GT 重新对齐尺度。
2. 对 relative/inverse-depth-like 输出先确定表示、转换和对齐规则，不把原始输出直接当米。
3. Middlebury：输入、GT、标定属于同一场景与分辨率；在提供 `doffs` 时使用 `Z = f * baseline / (d + doffs)`，输出统一为米。核对 OpenCV 视差缩放和标定长度单位。
4. NYUv2：核对 labeled 数据读取方向、单位、标准划分与预处理；不把无序单图串成视频进行时序评测。
5. 视频开发/测试按完整场景隔离，调参仅用开发集；所有方法使用相同帧与评测区域。
6. 融合算法内部拒绝历史信息的 mask 不得用来挑选评测像素。共同的评测有效区域必须独立定义；报告无效预测比例。
7. 无深度 GT 的视频只支持一致性/稳定性结论。相机移动引起的真实 Z 深度变化不能全部叫作漂移。
8. 光流只建立像素对应，不会把历史深度变换到当前相机坐标系；同时检查遮挡、前后移动、边界退化、拖影与响应延迟。

## 正确性检查与报告

- 在全有效且正深度的样本上，prediction = GT 时误差指标为 0，δ 指标为 1。
- 专门检查单位错误、尺寸错误、空有效区域、非有限值；不输出误导性的成功指标。
- 保存每个样本/片段结果，再生成汇总；保留原始预测用于独立复算。
- E0–E5 使用相同测试片段、分辨率、指标和评测 mask，参数在开发集确定后冻结。
- 结果表同时列明表示/单位、是否对齐、数据划分、配置、运行模式与开销。
