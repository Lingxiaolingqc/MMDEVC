# 数据量与训练收敛实验计划（2026-11-27）

本计划由 Qinchuan XIAO 于 2026-11-27 授权实施。目标是比较固定 Residual、LoRA 和联合训练组合在不同标注数据量下的最佳表现、训练稳定速度、停止时表现和增量收益。先完成开发实验，冻结模型和评测规则，再统一评测 NYUv2 官方 654 张 test。原始实验与冻结记录保持不变。

## 方法和数据

- R：冻结原始 UniDepthV2 Small，训练已选中的 decoder F3。使用 decoder init/mid/late 真实特征，投影宽度 6/5/5，一次拼接 RGB 和 log(depth)/2，经既有 CNN 输出加法残差。
- L：LoRA L_E_r8_lr3e4，encoder 第 9–12 个 block 的 attention qkv/proj，rank=alpha=8，dropout=0。
- J：上述 LoRA 与 F3 从官方基础权重、零初始修正共同训练；只更新 LoRA 和 F3，保留实时深度和三阶段特征的梯度。
- S：补充分阶段对照。加载同数据量、同种子 L 的 best 权重并冻结，重新训练 F3。它的总成本包含 L 的实际完整训练和选择过程。
- B0：0 张训练的原始 UniDepth，只评测一次，作为共享参照；不伪造三个独立种子。

577 张 fitting、218 张 validation 沿用 configs/edge_association_split.json，包含 187/62 个不重叠场景。test 不参与训练、早停或参数选择。种子固定为 320112、320113、320114。

训练子集大小为 100/200/300/400/500/577，全部名单在正式实验前冻结并严格嵌套。100 张来自 100 个具体场景，覆盖全部 22 种类别，兼顾类别比例；200 张覆盖全部 187 个 fitting 场景；之后逐轮补充仍有剩余图片的场景。场景及场景内图像按固定种子 320118 排序，不使用模型误差或 GT 挑图。训练种子不改变数据名单。100→200 同时改变场景覆盖和样本数，结论须说明这一点。

## 执行顺序

1. 固定名单、实现独立入口，完成单元检查、梯度/零修正/冻结检查、验证不更新状态检查及断点恢复检查。
2. B0 的开发基线。
3. 100 张：R 三种子 → L 三种子 → J 三种子。
4. 200 张：同上。
5. 400 张：同上。至此主优先实验共 27 个训练阶段。
6. 300 张：同上。
7. 500 张：同上。主必做实验合计 45 个训练阶段。
8. S 对照：100 张三种子 → 400 张三种子；复用已经完成的 L，新增 6 个 F3 训练阶段。
9. 补 577 张 R/L/J，共 9 个阶段。执行前记录磁盘、内存和预计新增存储。
10. 按 200 → 300 → 500 → 577 张补齐 S，每档三个种子，新增 12 个 F3 阶段。
11. 汇总开发分析、冻结所有 best/final checkpoint 身份与 test 评测清单，再统一评测 654 张 test；不得看完 test 再改方案。不开展全 795 张重训。

用户于 2026-11-27 补充：“stage也是如果时间够就把所有的数据量都补上吧。时间够指的是我没喊停就做”。因此没有任意时间截止点；未收到停止指令时持续推进全部 72 个训练阶段（六档非零数据量 × R/L/J/S × 三种子），共享 B0 不计训练。后列任务优先级较低，不因耗时自动省略。实际资源不足时先排查、保留状态，并如实报告。

## 训练规则

每个阶段上限 6000 次更新尝试，有效 batch=8；每 100 次评测完整 218 张 validation，记录 step 0。使用 AdamW，lr=3e-4，weight_decay=.001，6000-step cosine 至 1e-5，gradient clip=1，AbsRel loss，无增强。沿用 finite_rays_v2 的训练用有限 ray 梯度，官方前向保持不变。R/L/J/S 使用统一工程检查确定的 AMP 初始 scale=128；成功更新数与 AMP 跳步数分别记录。正式训练前检查完整有效 batch；若需梯度累积，在工程检查中确定并写入配置，不能训练途中静默改变。

早停至少训练 1000 次，监控 validation AbsRel。相对上次明显改善的参考值，累计下降至少 0.2% 才重置耐心计数；连续 10 次验证（1000 iterations）没有明显改善时停止。raw best 在每次严格下降时保存，不受 0.2% 阈值影响。最终权重另存 final.pt，不能用 best 覆盖 final。早停不会改变 cosine 的 6000-step horizon。

不同数据量、不同种子从官方模型独立初始化；不从 577 张已训练权重开始小数据实验。Joint 与独立 R 在同种子下使用相同 F3 初始化。Stage 的初始基础预测是对应 L，而不是 B0。

工程检查已定位：PyTorch 的 upsample_bilinear2d_aa_backward_out_cuda 不提供确定性实现（严格确定性检查会报错）。保持官方抗锯齿前向/反向，不替换算法；恢复参数必须逐位相同，恢复后下一步权重允许 atol=1e-7、rtol=1e-4 的数值误差并记录实测最大值。此容差在正式训练前确定，不用 validation 选择。不得将这种恢复宣称为整段训练逐位可复现。

## 收敛、性能与成本

- best：本次观察到的最低 validation AbsRel，记录其步数。
- final：实际停止时模型，记录停止原因（patience/max_steps/failure）。
- stable：最终连续至少 500 iterations 的验证点都不超过本次最佳 AbsRel 的 1.01 倍；否则不宣称稳定收敛。稳定步数为满足该条件并一直保持到终点的最早评测点。
- target：首次连续三个评测点达到 AbsRel≤0.10 或≤0.09；达不到写未达到。
- 记录 train/validation 全曲线、best→final 变化、有效 epoch、图像访问次数、成功/尝试更新、AMP 跳步、纯训练/验证/缓存/总耗时、参数与峰值显存。
- 所有 best/final 在完整 validation 上保存逐图 AbsRel、RMSE、delta1、边界 F1、边界带 AbsRel。报告三种子均值/标准差、稳定种子数、配对差异及按场景 bootstrap 区间，区分训练种子波动与场景不确定性。
- 固定样本可视化使用 NYUv2 ID 5/598/1440/226/246/80；同图同色标。助手实际看图后才能形成定性结论；难例挑选规则公开。
- Stage 报告完整 L 阶段成本 + S 阶段成本及新增特征提取，不能只算 best 所在步数。相同 iteration 不等于相同 FLOPs 或时间。
