## 4. 成员 A：具体任务

### A1. 整理 Middlebury 数据

**操作顺序：**

1. 获取 Middlebury Stereo v3 的 Quarter Resolution 输入和左视差 Ground Truth（GT）。
2. 检查要求使用的 15 个训练图像对是否齐全。
3. 逐场景关联左图、右图、GT disparity 和 `calib.txt`。
4. 读取一组样本，检查 RGB、视差图的尺寸、有效区域和数值。
5. 记录焦距、baseline、主点差 `doffs` 等标定信息。

**交付物：** 数据清单；一组左右图与 GT 的检查图；标定和单位说明。

**完成标准：** 输入、GT 和标定属于同一场景及分辨率，能够通过样本 ID 稳定读取。

### A2. 整理 NYU Depth V2 数据与评测规则

**操作顺序：**

1. 获取 labeled 数据及标准划分；使用课程指定的 labeled 部分。
2. 建立 RGB 与 depth 的一一对应关系。
3. 核对深度单位、图像方向、无效值、crop 和有效深度范围。
4. 按课程指定的评测参考实现，整理可复用的数据读取与评测预处理。
5. 从开发侧选少量样本供两人检查接口，并保留正式测试清单。

**交付物：** 样本与划分清单；读取入口；预处理和有效像素规则；共享的小样本检查清单。

**完成标准：** B 使用同一个样本 ID 能获得同一张 RGB、同一份 GT 和同一评测 mask。

### A3. 跑通单样本 StereoSGBM

**操作顺序：**

1. 在一对图像上计算 disparity（视差）。
2. 核对实现返回的视差数值尺度，转换到正确的像素单位。
3. 标记无效视差，检查 left–right consistency（左右一致性）。
4. 读取标定参数，将视差转换为深度。
5. 与 GT 比较，保存预测、有效区域和误差图。

**Middlebury 标定注意：** 当数据提供 `doffs` 时，按标定使用：

```text
Z = f * baseline / (d + doffs)
```

`f`、`d` 和 `doffs` 的像素尺度须与所用分辨率一致；`Z` 的长度单位随 baseline。不要重复缩放已经适配该分辨率的标定参数。

**交付物：** RGB、预测视差、GT 视差、预测深度、误差图和有效区域图。

**完成标准：** 结果没有明显的单位或数量级错误，并能解释主要无效区域。

### A4. 完成 15 对图像的双目基线

**操作顺序：**

1. 在少量开发场景上比较有限的参数设置，例如 block size 和平滑参数。
2. 固定配置，批量处理全部 15 对图像。
3. 记录逐场景误差、有效预测覆盖率和运行时间。
4. 挑选弱纹理、遮挡、重复纹理或远距离区域，分析失败原因。
5. 标明哪些场景参与了参数选择；完整 15 对的汇总不能被描述成全部独立的 held-out 测试。

**交付物：** 逐场景结果表、汇总结果、代表性图组和简短分析。

**完成标准：** 无遗漏场景；无效预测比例透明；能从保存结果重新计算指标。

### A5. 建立统一单图深度评测入口

**需要支持：** AbsRel、SqRel、RMSE、RMSE-log、δ1、δ2、δ3。

**操作顺序：**

1. 输入 prediction、GT、有效 mask 和明确的评测配置。
2. 处理尺寸、单位、有效范围及非有限值，并记录处理方式。
3. 区分 direct metric 评测与 relative/aligned 评测；对齐方式必须明确。
4. 用“prediction 与 GT 完全相等”的有效样本检查：误差指标应为 0，δ 指标应为 1。
5. 对 B 提供的一份真实预测运行评测，验证两人的接口一致。

**交付物：** 评测代码或入口、示例命令、样例指标、协议说明。

**完成标准：** B 可以独立调用；协议中没有混用米制深度与未转换的相对输出。

### A6. 试跑 UniDepthV2

**操作顺序：**

1. 按官方说明配置环境，默认先使用 UniDepthV2 ViT-S 的预训练权重。
2. 在少量样本上推理，核对输出尺寸、表示和单位。
3. 保存原始 metric depth，连接 A5 的评测入口。
4. 记录 checkpoint、输入配置、耗时和资源情况。
5. 将运行命令写入 README。

**交付物：** 可复现的运行说明、原始预测、可视化、初步指标和配置记录。

**完成标准：** 至少一个样本完整完成预测、保存和评测。直接 metric depth 不利用测试 GT 重新对齐尺度。

**A 同步写入报告：** 数据与评测规则、StereoSGBM 流程、双目初步结果、几何失败分析、UniDepthV2 配置。

## 5. 成员 B：具体任务

### B1. 跑通 Depth Anything V2 单图预测

**操作顺序：**

1. 按官方说明配置 Depth Anything V2，先运行 Small relative checkpoint。
2. 在一张 RGB 图像上推理。
3. 查清原始输出表示及数值方向，确认是否属于 inverse-depth-like prediction。
4. 保存未经显示归一化的原始预测，同时生成可视化。
5. 记录权重、输入尺寸、环境和运行命令。

**交付物：** 原始预测、单图可视化、推理命令及输出表示说明。

**完成标准：** 清楚说明数值含义；相对输出不直接标成“米”。

### B2. 接入 A 的 NYUv2 评测流程

**操作顺序：**

1. 使用 A 交付的小样本清单运行预测。
2. 与 A 共同确认相对输出的转换方式和协议允许的对齐方式。
3. 在评测记录中明确标注 `Relative + Alignment`，并记录具体对齐规则。
4. 将一份原始预测交给 A 独立复算，核对数值。

**交付物：** 少量样本的评测结果、转换/对齐说明和可复算的预测文件。

**完成标准：** 两人对同一预测使用相同规则时得到相同指标；不把对齐后的相对预测称作直接 metric prediction。

### B3. 采集、整理与划分视频

以下六类为小组建议的素材覆盖范围，每段可先拍 10–20 秒；数量和时长不是课程硬性规定。

| 类型 | 拍摄方式 | 观察目标 |
|---|---|---|
| 固定相机、静止场景 | 手机固定，拍桌面或房间 | 场景不动时预测是否抖动 |
| 固定相机、运动与遮挡 | 让物体或人经过前景 | 遮挡边界、新出现区域是否不稳定 |
| 相机横向移动 | 缓慢平移，保留近远物体 | 运动中的边界与预测稳定性 |
| 相机前后移动 | 向目标靠近后再远离 | 真实深度变化和预测响应 |
| 细结构 | 拍椅子腿、电线、栏杆等 | 细物体是否丢失或跳动 |
| 困难表面/成像 | 玻璃、镜面、暗光或模糊 | 收集后续失败分析素材 |

**操作顺序：**

1. 保存未经处理的原视频，给每段视频分配稳定的 `clip_id`。
2. 记录场景、拍摄方式、分辨率、帧率、时长和备注。
3. 开发与测试按完整片段/场景隔离，避免相邻帧分到两边。
4. 对关键场景保留独立测试素材，必要时补拍。
5. 若降低帧率或分辨率，保留变换记录，并统一各方法输入。

**交付物：** 原视频、素材清单、划分清单、帧/时间对应关系。

**完成标准：** 每份视频结果都能追溯到原始素材；开发与测试用途清楚。

### B4. 跑通逐帧视频处理

**操作顺序：**

1. 顺序读取视频帧，先用一个短片验证，再扩展到本周素材。
2. 用 Depth Anything V2 逐帧预测。
3. 按原始帧编号保存浮点结果，避免掉帧后编号错位。
4. 同一视频内使用固定的显示范围，生成 RGB 与预测并排视频。
5. 记录推理耗时；区分模型推理与包含读写、视频编码的总耗时。

**交付物：** 视频推理入口、原始预测序列、并排视频和运行记录。

**完成标准：** 帧对应关系正确；没有只保存彩色视频而丢失原始数值；没有逐帧独立归一化掩盖闪烁。

### B5. 诊断逐帧预测的问题

**操作顺序：**

1. 在固定相机的静止场景中选择固定区域，绘制原始预测统计量随时间的曲线。
2. 明确这些数值的表示和单位；相对模型的曲线描述为“相对预测值波动”。
3. 检查运动、遮挡、细结构和困难表面，记录具体 `clip_id` 与帧编号。
4. 每个案例写清楚“现象、发生条件、可能原因、待验证问题”。
5. 将最有代表性的案例交给 A，作为第二周融合算法的开发依据。

**交付物：** 静止区域曲线、带索引的问题案例、简短诊断文字。

**完成标准：** 能定位真实问题，而不只展示漂亮截图。无深度 GT 的视频不报告无法验证的绝对深度准确率；相机移动造成的真实深度变化不全部归为 scale drift。

### B6. 试跑 Video Depth Anything，建立报告骨架

**操作顺序：**

1. 按官方说明运行 Video Depth Anything-Small；优先试跑计划第二周使用的 metric checkpoint。
2. 处理一个短片，核对输出帧数、尺寸、单位和原始结果保存方式。
3. 记录使用 offline 还是 streaming 模式及对应配置。
4. 保存推理命令与视频结果。本周先验证流程，正式公平比较在第二周展开。
5. 建立 CVPR 报告框架，放入项目目标、数据表、方法占位、实验表和参考文献记录。

**交付物：** VDA 运行说明、原始预测及视频；报告框架；初版 README。

**完成标准：** VDA 能成功处理短视频，另一人可以根据说明重复运行。

**B 同步写入报告：** DA V2 配置、视频采集与划分、逐帧处理流程、可视化规则、闪烁和失败案例。

| 字段 | 内容 |

| `metrics` / `runtime` | 指标、有效覆盖率与计时范围；注明设备及运行模式 |

3. 保留原始预测、配置和可复现记录，便于继续实验。
4. 优先削减额外参数搜索、大模型对比和装饰性可视化，不挤占核心链路检查。
5. 如果某个模型环境阻塞，及时交接错误、版本和已尝试步骤；并行推进不依赖它的数据、评测或报告工作。
